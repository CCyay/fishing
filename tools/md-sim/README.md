# 摸打钓鱼 · 对局模拟器

离线跑对局、量技能强度的脚本。无依赖，`node` 直接跑。

```
node sim.js base                     跑基准（双方都没技能），对照设计文档的六个数字
node sim.js one hook                 量一件技能的分差
node sim.js one hook --role lock --slot 2    装在哪个角色的第几个槽
node sim.js all -n 40000             所有技能跑一遍，出一张表
node sim.js pair suitify suited      量两件装一起的分差（组合技的底数）
node sim.js cards                    零点牌 / 无点数牌掺进牌组、抹点抹牌，局面怎么变
node sim.js vs dredge calm           我带一件、对手带一件（反制型技能用）
node sim.js vs raise raise           同一件传两次 = 量它在先手/后手各值多少
node sim.js roles                    八个角色的常驻技能各值多少分
node campaign.js                     闯关十二关按难度跑一遍：每关胜率、通关率（难度校准用）
node fingerprint.js                  对一遍源码有没有动过（见下面「漂移」）
```

> **终局规则〔2026-10-15 改定〕**：三条，**成套的，拆开用会坏**：
>
> 1. **牌库空了，双方各再打 1 手就收摊**（`TAIL=2`，默认）
> 2. **一局里双方出牌数要相等** —— 不等的话少打的那一方补一手（`EVEN`，默认开）
> 3. **手里剩的和堆上剩的都不算分**（`BALANCE=old`，默认）
>
> 为什么成套：终局一缩短，后手优势就没了，再把剩堆判给谁都是过补 ——
> `TAIL=2` 配 `pileNotLast` 是 **−2.23**，配 `old` 是 **+0.31**。
>
> **2026-10-15 之前记下的分数全部不可比**：每人每局从 24.4 分掉到 21.8 分，
> 所以定价目标也从「一件 +3~5 分」降到 **+2.7~4.5 分**。
>
> 终局那几手的长度是这一版最敏感的旋钮（各 20000 局）：
>
> | 无补充阶段 | 8 手（旧规则） | 4 手 | **2 手（现行）** | 0 手 |
> |---|---|---|---|---|
> | 后手分差 | +3.03 | +0.82 | **+0.31** | +0.33 |
>
> 2 手和 0 手统计上分不开（差 0.02，标准误 0.08），取 2 手是为了手感
>（手里的牌还能打一张）和摊薄「抽空牌库提前收摊」的收益。
>
> 对照档：`TAIL=999`（打完手牌）、`BALANCE=pileNotLast`（剩堆归没打最后一手的）、
> `EVEN=0`（关掉补手）。几个只做实验用的旋钮：`HAND_SIZE`（手牌数）、
> `BAL_K`、`DROP`（开局多剔几张，量奇偶用）、
> `SURGE_*`（【引潮】/【推牌】原型，游戏里还没有这件技能）。

> **切牌定庄〔2026-10-15〕**：开局翻牌库顶那张 —— **红 = 庄家先手、黑 = 玩家先手**，
> 那张牌进先手的手牌而且对手看得见。
> `CUT=0` 关掉切牌（庄家恒先手，量旧口径用）。
>
> 它当初治的是「`pileNotLast` 之下剩堆每一局都归先手，而闯关里先手恒是庄家」。
> 剩堆不算分之后那个理由没了，但它**留着**：先后手仍有 +0.31 的残余，
> 而且「切牌定庄」是实体牌桌上现成的仪式，不用解释。
>
> 开局那道剔牌闸也还在，但**换了两处**（`DECK_SIZE` 跟源码的 `DECK_PLAY`
> 一起删了）：不再剔到 52 张（牌组可以任意厚），现在**只剔 0~1 张**，
> 凑的是「**发完牌之后的牌库**是偶数」。
>
> 为什么还要这道闸 —— `DROP` 旋钮量的（`TAIL=2 BALANCE=old`，各 20000 局）：
>
> | `DROP` | 0（52张偶） | 2（50张偶） | 1（51张奇） | 3（49张奇） |
> |---|---|---|---|---|
> | 无 `EVEN` | +0.31 | +0.30 | −0.90 | −0.91 |
> | 有 `EVEN` | +0.31 | +0.30 | **−0.38** | **−0.40** |
>
> 奇数牌库下先手多摸一张 → 牌库空在他的回合末 → 终局变成「后手打、先手打、
> 后手打」（后手打两手、其中一手被回应），而偶数时是「先手打、后手打」
>（后手那一手 100% 无人回应）。`EVEN` 只补回 43%，剩下的 0.69 分是结构性的。
>
> **锁牌库而不是锁牌组**：发几张走 `handLimit`，而【添手】/【掐口】会让发牌
> 总数变成奇数 —— 那时「牌组偶数」正好得出牌库奇数。原先那道闸漏了这两条。
>
> **只有 `base` 走自由切牌**，别的命令写死庄家先手（`sim.js` 的 `fixFirst`）——
> 「这件技能在先手手里值多少 / 后手手里值多少」那套口径（A / D 两格）
> 靠「配装给 ME 还是给 FOE」来区分，先后手一随机两格就都成了「一半一半」。
> 所以 `all` / `roles` / `one` 的数跟 2026-10-15 之前**可比**，`base` 的不可比。
> `campaign.js` 走自由切牌（闯关里现在也切牌）。
>
> 剔牌和切牌的位置是硬性的：**剔牌在囤饵之后**（它塞 3 张，奇数，会绕过偶数闸）、
> **切牌在 rankTotal 之后**（切出那张仍在局内，得算进庄家记牌的底数）。
> 源码那边同一个顺序（`ap-fishing.uvue` 的 `trimDeck` 和它下面那段）。

## 为什么有这个东西

设计文档《摸打钓鱼-技能与关卡设计.md》里那些数（「每人每局钓到约 9 次」、
「磁钩满装 +7.0」）是当初用一次性脚本跑的，**脚本没留下来**。
后来加的技能（换水起的那九件）因此一件都没校准过，价钱是照同类件抄的。

v3 的三件事都卡在这上面：七个技能校准、组合技、产金币。所以它是第 0 批。

## 它不是游戏代码的一部分

`rules.js` 和 `ai.js` 是 `pages/examples/blackjack/ap-fishing.uvue` 的**手写副本**。

为什么不复用源码：项目的 `package.json` 里 `dependencies` 是空的，没有
esbuild / tsc 能把 `.uts` 的类型注解剥掉给 node 用；而对局规则长在 `.uvue`
的 `<script>` 里，缠着 `ref` 和 `setTimeout`，抽不出来直接跑。
把规则重构成一个纯 `.uts` 模块是另一条路，但那要动那个 2285 行的页面 ——
风险远大于一个只读的副本。

副本的代价是**会过期**。所以配了 `fingerprint.js`：源码里那几个关键函数
一改，它就报出来（见文末）。

## 同步状态（2026-10-10）

> 这个模拟器是**几次接力**做出来的。这一节记「搬到哪了」和「哪些差异是故意的」——
> 不然下一轮会把有意的简化当成 bug 去「修」，或者把已经搬好的再搬一遍。

**搬到的源码状态**：「先结算技能、再匹配」那次重构之后
（`playFor` 只落堆 → `afterPlay` 结算技能 → `resolveMatch` 拿下来对剩下的堆判）。

- `resolveMatch`：`removePileAt` 再判、J 落空堆只勾走自己（1 分）、
  稳钩在这一步护上、钓到那一段的区间（含 sink 镜像的 `at + 2`）

  拼起来**一字不差**：量水 → 窥视 → 照水 → 压邻 → 封色 → 分水 → 掏手 → 掏库

  → 冻结 → 换水 → 择饵 → 同花 → 同号 → 观潮

### 三个「积压漂移」核对完了，都不是漂移〔2026-10-16〕

`fingerprint.js` 报 `playFor` / `afterPlayTail` / `endPlay` 三个函数正文变了，
而它们**不是**那一轮的改动，看着像积压了好几轮没核。逐个核过之后：

| 函数 | 源码变了什么 | 模拟器 | 判定 |
|---|---|---|---|
| `endPlay` | 删掉 `fillPond(byFoe)`（填塘重做成【净滩】，判在打出那一刻） | 也删了同一行 | **同步** ✓ |
| `afterPlayTail` | 清掉退潮 / 洪水两条死分支 | 有意保留（见上表最后一行） | **行为一致** ✓ |
| `playFor` | 去掉【寒流】的「同花色」限制 | **2026-10-14 就去掉了** | **源码在追赶副本** ✓ |

> 第三个那个方向值得记住：**漂移不一定是「副本落后」**。
> 模拟器是试验场，所以新规则常常先在这儿定稿、过几天才搬进源码 ——
> 那期间 `fingerprint` 会报源码「变了」，而真相是**它终于跟上了**。
>
> 所以核对的问法不是「副本补上了没有」，是「**两边现在是不是同一个行为**」。

另外两类差异在这次核对里也确认了，都在上表里：推牌的调用位置不同
（源码在 `endPlay` 内、模拟器在 `playFor` 里 `endPlay` 之前）但**都在
`passTurn` 之前、且只在真打出一张牌时触发**，等价；以及模拟器的
`G.stat.plays[side]++` 对应源码的 `foePlayed` / `myPlayed`。

   **但它的三个数一个都没跑过** —— 21 / 至少 2 张 / 标价 150 全是手算。

1. ~~一次都没跑过~~ —— **`base` 和 `all` 跑过了**（2026-10-10 起）。

### 这一轮查出来的两件事，都还没修

**一、`ai.js` 的 `wants` 在给无效技能倒扣分。**

窥视 / 照水 / 染水的 X **完全相同**（−0.19，标准误 0.12）。原因：
三件都在 `pickCard` 的 `wants` 列表里（「想当饵顺手发动」给 −1.5 的优先），
**可它们的效果对这套启发式是 0** —— 于是 AI 为一个无效的技能打次优牌。

对照组印证：归深 / 软点 / 沸水 的效果同样是 0，但它们**不在 `wants` 里**，
X 就是干净的 **0.00**。

> 所以那 −0.19 **不是技能的成本，是启发式的愚蠢**。
> 后果：**那三件的真实强度从没被量过**，而且凡是
> 「在 `wants` 里但对 AI 无效」的件都带着这个偏差。

**二、旋钮的默认值必须跟着定稿翻。**

涉水定稿成「可以不参与」（+2.08）之后，`WADE_SELF` 的默认值忘了从
`!== '0'`（= true = 必须参与）翻过来，于是 `all` 表把它当**旧档**量了
（报 +1.03，而那是「必须参与」那一档的数）。已修。

> **旋钮的默认值就是「游戏里那件技能的样子」。** 改定稿必须一起翻，
> 不然这张全表会拿旧档的数去定新档的价。
>
> 这一次是 `all` 发现的 —— 单件量的时候看不出来，一上全表就对不上。
> **那是跑全表的一个额外价值：交叉验证。**

### 「在场效果」和「存着的值」必须是两个函数（焦壳逼出来的）

`pileValsAt(G, i)` 以前就是 `G.pileVals[i]` 的取值器 —— 全表**没有一件**
技能会「在场期间改堆上的点数」，所以读和存是同一回事。

【焦壳】（在场时带燃烧的牌无点数）是第一件，于是坑露出来了：有**三处**
在**写** `G.pileVals`、却从 `pileValsAt` 读。焦壳在场时它们会把「空点数」
**写死**进存储，焦壳离场也不还原 —— 在场效果变永久。

| 位置 | 它在干什么 |
|---|---|
| `harvestAt` | 收牌后重建那六条平行数组 |
| `ebbFor`（退潮） | 堆顶几张各减点数 |
| `dropPile`（见底一族） | 整堆各减点数 |

修法是拆成两个函数，按**用途**分而不是按数据分：

```js
rawVals(G, i)      // 存着的点数。**写 pileVals 的一方读这个**
pileValsAt(G, i)   // 现在算几点（带在场效果）。**判定的一方读这个**
```

> 判据很好记：**你这一行会不会写回 `G.pileVals`?** 会，就用 `rawVals`。
> 合流和抬水逃过了这一劫，不是因为写对了，而是它们都有「空点数就 return」
> 的前置闸 —— 那是运气，不是设计。
>
> 这一条**对游戏代码同样成立**：`ap-fishing.uvue` 里是同一个结构，
> 焦壳搬过去之前要先拆这两个函数。
2. `fingerprint.js` 的基准**还是没重存**，但那个「18 个函数待核对」的
   积压 2026-10-16 清掉了。
   〔那一版的原话：基准连 `draft` / `soft` / `dead` 和叠放那五件都没有，
     两个常量变了，18 个函数正文变了。中间 `--save` 过一次，
     所以后来只剩 3 个积压。〕

   **2026-10-16 的状态**：报出来的差异全部核对过，**没有一个是真漂移** ——

   - 三个积压（`playFor` / `afterPlayTail` / `endPlay`）→ 见上面
     『三个「积压漂移」核对完了』那一节；
   - 当天这几轮改的（`straightFor` / `straightCount` / `foePickCard` /
     `afterPlayHead`）→ 都是双边同步改的；
   - 三张表（33 技能 + 9 常驻 + 9 角色）和 `CLEAR_OPEN`（3→4）两边一致，
     `refs.js` 九项全过。

   > 所以 `--save` 的前提现在**真的**满足了。
   > 但记住它的含义没变：**存下去就等于声明「两边是同一个行为」** ——
   > 所以每次 `--save` 之前都要像这次一样把名单过一遍，
   > 而不是因为「噪音太多看不下去」才存。
3. 【枯水】**量不了** —— 它是庄家的关底规矩（挂在雾港守灯人那一关），
   而模拟器不跑闯关关卡表（见下面第 9 条）。
   〔那句「【涨落】可以量：`node sim.js roles` 会把【候潮渔翁】跑进去」
   2026-10-16 作废 —— **量了，所以它删了**（常驻 X=−8.87、D=+0.90，
   全表唯一超 2σ 的）。这一条现在是个好例子：量得出来的就该量，
   而那一次量出的数直接废掉了一整张角色卡〕
4. **叠放那五件搬完并量过了**（2026-10-10，细节见 `rules.js` 的 `SK` 表下面那段）。
   它没有变成第七条平行数组（叠着的牌压根不在堆上），真正改掉的只有
   **收牌**：两条路（区间 `collect`、散收 `harvestPile`）汇到了同一个
   `harvestAt`，逐格走 `takeAt`。`base` 跑过了，六个基线数和牌数守恒全对上。

   第一批数（江口闸官第一槽、20000 局、标准误 0.12）：

   | | 分差 | 读法 |
   |---|---|---|
   | 抬水 | +1.50 | 四件里唯一正的。启发式算得准（整堆是明的） |
   | 净水 | −0.24 | 启发式粗，量的是「它打得多好」不是天花板 |
   | 凝水 | −0.29 | 同上 |
   | 抄底 | −0.92 | **这个数不是抄底** —— 见下 |
   | 合流 | −1.13 | **设计判断被推翻了** —— 见下 |

   - **合流**：注释里写着「三样好处、没有自带坏处」，所以价钱从 130 提到 150。
     实测是负的。错在把「多一个匹配点」只算成自己的好处 —— **匹配是双向的**，
     多一个钓点等于多一条别人钓它的路，而它底下压着一张、被钓走就送 2 分。
     那两条互相放大。完整的分析和三个可选方向写在 `draw-skills.uts` 合流那条。
   - **抄底**：它是**反制型**的，而这套工具原先量不了 —— 见下面第 5 条。
     `all` 的 −0.92 量的是「一张无点数的废牌值多少分」（场上没叠放，它永远掀空），
     那正好是它「无点数是兜底不是代价」的**下限**。
   - 凝水 / 净水 / 抬水在游戏里要玩家点堆上一张，这边是启发式（`pilePick`）。
   - 收成不再等于区间长度（被埋的牌跟着走、带盾的宿主留下），所以 `caught`
     的口径变了 —— base 不受影响（没技能就没有叠放），但带这几件的配装
     不能跟旧数据比。
5. **`vs` 子命令是新加的（2026-10-10）。**
   搬抄底的时候发现一个**框架级的空缺**：原先六个子命令**一律给对手传
   `emptyLoadout()`**，于是一件「专门用来破对手某样东西」的技能永远无事可做，
   量出来的不是它的价值，是一张废牌的价值。
   `pair dredge calm` 也不行 —— 那两件都在**我**这边，等于我垫盾再自己掀掉
   （协同 −0.15，那是「对双方都生效」的设计后果，不是它的用法）。

   `vs` 把配装分到两边，而且跑的是一个 **2×2**（我带/我空 × 对手带/对手空），
   报的是**差中之差** —— 「对手带了那件」让我这件多值的分。
   为什么非得四格：拿它跟 `one` 比是**错的**，`one` 的对手不带角色，
   两个数的基线口径不一样，相减会混进「对手白得了一个角色」的影响。
   （第一版就犯了这个错，四格是修正后的版本。）

   抄底对四支叠放全量过了。把「那件对**对手自己**值多少」摆在旁边，
   模式就出来了：

   | 对手带的 | 对对手自己值 | 抄底的差中之差 |
   |---|---|---|
   | 抬水 | +2.80 | +1.54 |
   | 净水 | +1.23 | **+1.68** |
   | 凝水 | +0.61 | +1.27 |
   | 合流 | **−0.83**（自损） | **−0.86** |

   **对手那件越有用，抄底反制它越值钱。** 三支都在 +1.3~+1.7，所以
   「一件答得完一整族」那条定价理由是成立的。合流那个负数是**合流自己
   的毛病在抄底身上的投影** —— 它堆的叠是摆给我的赏金（我钓牌率更高、
   更可能收走），我去掀等于替对手解套。合流修好之后这一格该转正。

   **这里走过一个弯路，记着别再走**：第一版诊断说「抄底反制的是保护
   （`STACK_WARD`）不是叠放」，结果被净水证伪了 —— 净水垫的也是
   `STACK_BURIED`，却是全组最高。`kind` 不是区分因素。

   定价上理由立住了但数撑不住 160：最有利时也只有 +0.54~+0.95，
   目标档是 +3~5。完整分析在 `draw-skills.uts` 抄底那条。
   这批数是**下限**：模拟器的凝水/净水走粗启发式，垫的盾少。

   这条空缺不只影响抄底 —— **全表所有反制型的件都该用 `vs` 重量一遍**。
6. **第二个框架盲区：`all` / `one` / `pair` 只量「我」（后手）带技能。**
   `vs` 的四格顺带算出了另一侧，所以它现在也报「那件对**对手自己**值多少」
   —— 对手是先手，那是全套工具里唯一一个「技能在先手手里值多少」的数。

   第一个数就撞上了问题：**抬水在先手手里值 +2.80，而 `all` 里（后手）
   只有 +1.50。** 口径差解释不了这么大的缺口 —— 同一件事（对手空手时的
   抄底）`vs` 报 −0.73、`all` 报 −0.92，差只有 0.19 量级。

   **怎么干净地验证**：`C − A` 那两格都是「我空手」，所以 `mine` 压根不进
   那个计算 —— 参考行对任何 `mine` 都一样。于是**把同一件技能传两次**：

   ```
   node sim.js vs raise raise
   ```

   `D − C` 是它在后手手里的值、`C − A` 是先手手里的值，同一基线、同一角色、
   同一槽，两个数可以直接比。报表识别了这个特例并换一套措辞。

   **跑了四件（各 20000 局，标准误 0.12）：**

   | | 后手 | 先手 | 先手−后手 | `all` 报的 | 口径偏差 |
   |---|---|---|---|---|---|
   | 洪水 | +3.08 | **+7.35** | **+4.27** | +4.31 | **−1.23** |
   | 抬水 | +1.98 | +2.80 | +0.82 | +1.50 | +0.48 |
   | 齐顶 | +4.66 | +4.65 | **−0.01** | +4.40 | +0.26 |
   | 合流 | −1.00 | −0.83 | +0.17 | −1.13 | +0.13 |

   **两条都是因技能而异的，不是常数** —— 这推翻了中途那个「先手溢价是
   普遍的、`all` 系统性低估约 0.5」的简化说法（那只是抬水一件的数，
   而洪水的口径偏差是**反向**的）：

   - **先手溢价跨度 −0.01 ~ +4.27。** 齐顶完全没有（它只认「堆上最大的
     点数」，跟谁先打无关）；洪水巨大。
   - **口径偏差跨度 −1.23 ~ +0.48。** 所以不能拿一个修正值去调整 `all`
     整张表 —— 要准就得逐件跑 `vs <key> <key>`。
     `all` 的**排序**仍然可信（四件的相对位置没变），**绝对值**不可信。

   **洪水那个 +4.27 是个真实的平衡问题**：它在先手手里值 +7.35，
   而设计目标是单件 +3~5。
   机制上的猜测（**没验证**）：洪水是「从牌库往堆上翻，直到撞上点数，
   收走那一段」，所以**堆越空它收得越多** —— 先手第一手堆是空的，
   它等于「翻到出现一对为止，然后全收」。
   `我空 / 对手带洪水` 那格是 −5.40、胜率 32%，全表最狠的单件效果。
   顺带它还吃牌库（游戏变短），那对先手更有利。

## 验收：先跑 base

规则实现忠不忠实，不靠读代码确认，靠**对数字**。`base` 跑的是「双方都没技能、
都会记牌」，对照的是设计文档第一节那张表：

| 项 | 设计文档（模拟 4 万局） |
|---|---|
| 每人每局出牌 | 26 次 |
| 每人每局钓到 | 约 9 次（出牌的 34%） |
| 每次平均收 | 2.75 张 |
| 每人每局积分 | 约 24 分 |
| J 通吃占所有钓牌 | 22% |
| 先后手 | 后手赢 57–59% |

这六个数都对得上，说明判定、回合流转、庄家策略三块都搬对了。
**对不上就先别信任何技能数据** —— 回去查 rules.js。

（「每人每局出牌 26 次」是最硬的一条：52 张牌两个人分，无技能时必须正好 26。

## 量技能：口径

```
node sim.js one hook                 # 装在默认角色（江口闸官）第 1 个槽
node sim.js one hook --role basket --slot 1
node sim.js all                      # 所有点数技能一张表
node sim.js roles                    # 八个角色的常驻特殊技能
node sim.js role night               # 夜钓客打满槽
```

做法是**同一批种子跑两遍**：一遍基线，一遍一方带技能。
两遍开局牌序一样，所以差出来的就是技能本身。报出来的分差**已经扣掉**
后手那点固有优势（基线分差，base 命令末尾也会印）。

一起报标准误 —— 一个 `+0.3 ± 0.4` 的技能和一个 `+4.1 ± 0.3` 的不是一回事。
想把标准误压到 0.1 以下，`-n` 开到 4 万。

### 覆盖面由角色的槽决定，所以量技能必须先说「装在谁身上」

技能本身**不带覆盖面** —— 它管几张牌全看插的那个槽印着什么。
所以 `one` / `all` 有两个参数：

- `--role`（默认 `lock` 江口闸官）—— 它是 `['A','2','3','4']`，四个等大的小槽，
  全表最中性的尺子。换成别的角色（比如逆流船夫 `['5 6 7','4']`）量出来的数
  **不能跟这一列比**
- `--slot N`（默认 0）—— 插第几个槽，从 0 数

### 量技能**不带常驻特殊技**（口径，2026-10-13 起）

角色在这儿只提供**槽的形状**。`one` / `all` / `pair` / `vs` 四个子命令
一律把那个角色的常驻技**关掉**，要带就显式加 `--special`。
报表抬头会打「不带常驻技」/「带常驻技【某件】」—— 不打的话新旧两批
输出长得一样，而它们不可比。

实现上这是免费的：覆盖面走 `kitWithOne` / `kitFromRole` 产出的 loadout，
那条路跟 `G.roles` 完全无关（`rules.js` 里只有 `hasSpecial` 和囤饵的
`baitRankOf` 读 `G.roles`，而囤饵本身就是常驻技）。

`roles` / `role` 两个子命令反过来：槽空着（或打满），量的就是常驻技本身。

#### 原先那条「基线也带同一个角色就抵掉了」是错的

旧口径是「基线也带同一个角色、所有槽空着，相减就抵掉常驻技」。
那条**只在常驻技的影响可加时成立**，而它不一定可加：

| 角色 | 常驻技 | **基线格**（双方槽全空）|
|---|---|---|
| 江口闸官 | 窄口 | +1.94 分 / 胜率 54.5% |
| 候潮渔翁 | 涨落 | **−12.23 分 / 胜率 11.2%** |

【涨落】是「手牌 6 张、只在一张牌都打不出时才补」—— 补牌的粒度从
每回合 1 张变成一次 6 张，而先手永远在周期上领先一步。
基线歪 12 分，四格相减出来的就全是噪声。

> 更要命的是它**伪装成结论**：野火在候潮渔翁上报「先后手差 21.19 分」，
> 一眼看过去像「机制出了环」，其实那是基线的歪被技能抹平一半之后的残差。
> 换角色量到的反常数字，**先回头看基线那一格**。
>
> 一般化：镜像（双方同角色）只抵得掉**偏某一方**的东西，
> 抵不掉**偏先后手**的东西。而这个玩法的后手优势只有 1.94 分 ——
> 基线太薄，任何偏先后手的机制都能把它冲掉。

> ⚠ **【候潮渔翁】和【涨落】2026-10-16 删了**（常驻 X=−8.87、D=+0.90）。
> 上面这张表和整段推理**一个字都不删** —— 它讲的是量法
>（基线不能借、残差会伪装成结论），跟那件技能还在不在表里无关。
> 只是别再照那几行去跑命令：`--role tidal` 现在查不到。

### 这个文件里还提到哪些已删的技能

`peekFor` / `floodFor` / `dumpFor` / `spillFor` 那一类函数名、
以及「窥视 / 照水 / 染水的 X 完全相同」那条历史记录 —— **都是有意留着的**。
它们是**量法教训的载体**，而教训比技能活得久（上面那条「残差伪装成结论」
就是候潮渔翁留下的）。判断标准很简单：

- **讲量法 / 讲判据的** → 留，顺手标一句「这件已删」；
- **给出可执行命令的** → 必须改或标失效，不然下一个人照着跑会报 key 查不到。

### 跟 v2 那张表对不上是正常的

设计文档 v2 的「满装分差」是**老槽规则**算的：点数技满级管 6 个点数、
花色技满级管一整个颜色。那套模型整个没了（花色槽砍了、等级删了），
所以 v2 那一列只能当历史看。

## 量【吃水】：要回答的四个问题

规则：打出后从堆顶往下累加，总和不超过 `DRAFT_CAP` 的那几张连它自己一起收走。

- **它自己的点数吃预算**（`DRAFT_COSTS_SELF`）→ 打小牌收得多、打大牌可能空手
- **堆上吃不到 2 张就算没成**（`DRAFT_MIN`）→ 堵住「稳赚 2 分零风险」

三个旋钮都认环境变量，所以扫一遍不用改文件：

```
node sim.js base -n 4000                              # ① 先过验收
node sim.js one draft -n 40000                        # ② 默认档（CAP 21、MIN 2）
for c in 15 18 21 24; do DRAFT_CAP=$c node sim.js one draft -n 20000; done   # ③ 扫上限
DRAFT_MIN=0 node sim.js one draft -n 20000            # ④ 不设「至少 2 张」那道闸
DRAFT_COSTS_SELF=0 node sim.js one draft -n 20000     # ⑤ 「打小牌收得多」值多少分
node sim.js one draft --role mirror --slot 0 -n 20000 # ⑥ 插花色槽有多炸（镜湖占卜师 ♥）
```

| 要回答 | 看哪个数 | 手算的预期 |
|---|---|---|
| **它超标吗** | ② 的分差 | **~3.6 分/局**（目标 3~5）。加了 MIN 那道闸之前手算是 ~6 |
| **那道闸值多少** | ④ − ② | 手算 ~2.4 分。它同时把成功率从 ~91% 压到 ~53% |
| **上限定几** | ③ 那一列 | 挑最接近 4 分的。21 是 blackjack 的锚，但锚可以让 |
| **决策值多少** | ② − ⑤ | 「打小牌收得多」的价值。A 成功率 88%、K 只有 17%（5 倍差）—— 要是 ② ≈ ⑤，说明 AI 没在用这个决策，那是 ai.js 的缺口不是技能的 |
| **花色槽多炸** | ⑥ ÷ ② | 手算 ~3.3 倍（约 12 分/局）。所有技能通用是定死的规则，所以这个倍数**只能接受** —— 它决定标价，不是要不要拦 |

手算那几个数的来路：预算 = 21 − 牌面点数，要吃到 2 张就得
`你的点数 + u₁ + u₂ ≤ 21`。三张平均 7 点、和正好 21，所以成功率卡在一半上下：

| 你打的牌 | 预算 | 成功率 |
|---|---|---|
| A | 20 | 88% |
| 4 | 17 | 73% |
| 7 | 14 | 54% |
| 10 | 11 | 33% |
| K | 8 | 17% |

两条已知的、**不该当 bug 修**的：

- **沉底时不判吃水**（`catchStart` 里那个 `!sink`）—— 你这张落堆底，
  而它从堆顶往下数。两件撞在同一张牌上是真冲突，跟退潮一个毛病。
- **无点数断链**（`draftReach` 里 `vals.length === 0` 就 break）——
  那是吃水的反制：对手往堆顶丢一张顺色 / 封色 / 压邻过的牌就封掉它。
  0 点牌相反，加 0、不断链，是**免费垫片**。

## 没有建模的东西（看数据之前先知道）

1. **信息类技能的价值**：它们只给信息，而模拟里的策略**不用**对手手牌的信息
   （`ai.pickCard` 只读牌库残量，照 `foePickCard`），所以这一族跑出来接近 0。
   设计文档写的也是「只有信息，没法模拟」—— 口径一致，不是 bug。
   真要量它，得先写一个会利用情报的策略，那是另一个课题。

   〔2026-10-16 **试过一次，结论是这条路走不通**：`ai.js` 加了 `AI_SEEN` 旋钮
   （把看得见的牌从 `outsideCount` 的概率里拆出来当确定威胁算），
   拿窥视当探针扫权重 1/2/3/5/8 —— **全是统计零，而且 5 和 8 逐位相同**（饱和）。
   原因一句话：**避开风险的代价等于风险本身**。
   那一轮之后这一族四件删了三件（窥视、照水、活水），只剩【清水】，
   而清水是靠「常驻 + 够量」（3 张）才量出 +2.97 的。
   旋钮默认关，留着当「这条路走不通」的证据〕
2. **玩家侧也是 AI**：游戏里你是人。模拟里两侧同策略 —— v2 那些基础数据
   标的就是「双方都会记牌」。
3. **商店、金币、牌组改造、关卡表**：一概不参与。模拟器只管一局之内的事。
   想跑改造过的牌组，给 `playGame` 传自定义 `deck`（`rules.makeCard` 造牌，
   `extra` 就是点数卡贴的那几个点数）。
4. **点数卡**：规则实现了（`cardVals`、见底时每个点数各自压），但默认牌组
   是干净的 52 张。
5. **「每人每局出牌 26 次」只在无技能时成立**：连竿让一方一回合打两张，
   所以带连竿那边出牌数会高过 26 —— 两人合计仍是 52。`base` 跑的是无技能，
   所以那条验收不受影响。
6. **信息类特殊技能【清水】跑出来恒为 0** —— 同第 1 条，AI 不读情报。
   `roles` 那张表会给这行打 ⚠ 标出来。这不是实现错了，但它顺带说明一件事：
   **它的幅度不能按「双方都强」定**（设计文档 13.10）。
   〔原先这条写的是「清水、活水」两件 —— **活水 2026-10-16 删了**，
   而它死在一个更细的分别上：`AI_SEEN` 那个旋钮只拆「对手手牌」那一侧，
   `pickCard` 压根不读牌库，所以**连旋钮都覆盖不到它**。
   清水是对方手牌、活水是牌库顶 —— 这两件从来不重复，别再合写〕
7. **效果实现了但跑不到的**：
   - **【稳钩】**（`firmGuardFor`）—— 没有角色带它（磐石删了）；
   - **【活水】【涨落】**—— 两张载体角色 2026-10-16 删了。
     `SP.LIVEWATER` / `SP.CYCLE` 两个 key 故意留着（删了会变 `undefined`
     → `hasSpecial` 误匹配），所以这两条实现是**确定跑不到**的死代码，
     而不是会悄悄生效的。
   三件都不在 `roles` 那张表里。
8. **【逆流】量出来的是下限，而且原因在源码里**：
   - 落点那一步两侧都走庄家那套算法（哪头收得多往哪头落、钓不到就不落堆底），
     所以它反映的是一个**会算账的玩家**，不是随手按开关的手感；
   - 但**挑牌**那一步不算逆流 —— 源码的 `foePickCard` 那行写的是
     `const sink = hasTrigger(skills, SK_SINK)`，只看点数槽那件。
     挑牌阶段不知道「这张沉底能钓到」，而 `wantSink` 只在打出之后
     决定落点，牌已经挑定了。**这是源码的缺口，模拟器照搬**
     （见 `ai.pickCard` 那段注释）。所以 `roles` 报的逆流偏低。
9. **庄家关底规矩（第十节）** 和**闯关关卡表**：都没做。
   模拟器只跑「两个角色对打」那种终局结构。

## 漂移

```
node fingerprint.js --save    # 第一次，或者改完模拟器之后
node fingerprint.js           # 跑数据之前对一下
```

它把源码里那几十个关键函数的正文（剥掉注释和空白）、常量、以及
`draw-skills.uts` 里所有 `key: 'x', name:` 的顺序存成哈希。
那个 key 串一次抓三张表（`DRAW_SKILLS` / `SPECIAL_SKILLS` / `DRAW_ROLES`），
所以增删任何一件技能、特殊技能或角色都会报出来。

源码一动就报，按组列出改了哪几个 —— 然后人去核对 `rules.js`。
它**不判断**改动有没有影响结果，只回答「动过没有」。注释改了不报警。

## 要加东西的话

- **加一件点数技能**：`rules.SK` 加常量（下标照 `draw-skills.uts` 的表序）、
  `SKILLS` 表加一行、在 `afterPlay` 或 `catchStart` 里接上效果。
  `all` 会自动把它跑进表里。
- **加一件特殊技能**：`rules.SP` 加一个 key（**不是下标** —— 特殊技能按 key
  认身份，删一件不会错位）、`DRAW_ROLES` 加带它的那个角色、
  在对应的判定点读 `hasSpecial(G, side, SP.X)`。`roles` 会自动跑它。
  要是它只给信息（AI 不读），记得往 `SP_NOTE` 加一行说明，
  不然它那一行的 0 分差看着像实现错了。
- **组合技（第九节）**：在 `rules.afterPlay` 开头拿 `skills`（那就是 `triggersOf`
  返回的二元组）查一张组合表，命中就加那条效果。
  底数用 `sim.js pair A B` 先量 —— 它报的「协同」是**没有**组合技时两件技能
  互相影响的量，组合技做完再跑一遍，差额就是组合技自己的贡献。
- **庄家关底规矩（第十节）**：规矩是整局生效、不挂在牌上的，所以给 `newGame`
  的 opts 加一个 `rules: ['hardshell']`，在对应的判定点读它
  （硬壳在 `catchStart` 的命中判定、逆钩在 J 那一支、涨潮在 `refill`）。
